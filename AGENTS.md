# AGENTS.md — Palworld Save Pal (PSP)

Palworld save-file editor. Rust backend (Cargo workspace at repo root) +
SvelteKit frontend (`ui/`). Ships three ways from one codebase: Tauri desktop
app (primary), Docker/web (Axum server serves the SPA), and a browser-only
WASM webapp (`palworldsavepal.app`, Cloudflare Worker via `wrangler.jsonc`).
The old Python/FastAPI backend is retired; a legacy `psp.db` found next to
`psp-rs.db` is backed up and imported once on first start.

Read before touching sensitive areas: `docs/rust-dev-guide.md` (backend) and
`contract/README.md` (wire protocol). Note the dev guide's crate table
predates `psp-app`/`psp-web` and its uesave branch name is stale — root
`Cargo.toml` is the source of truth.

## Repository layout

| Path | Role |
|---|---|
| `psp-core` | Domain logic: save sessions over uesave-rs, DTOs (`dto/`), game-data loading, breeding solver, blueprints, transfer/steam-id logic. No web deps. |
| `psp-db` | SQLite persistence behind the `DbDriver` trait (`driver.rs`): settings, presets, UPS, servers, blueprints. Embedded migrations in `psp-db/migrations/` (0001–0007). **Sqlx-free by default**; the `sqlx-driver` feature opts into `SqlxSqliteDriver`. |
| `psp-app` | Transport-free app layer: `messages.rs` (protocol vocabulary), `dispatcher.rs`, `handlers/*`, `AppState`, `SessionStore`. Runs natively **and** on wasm32. |
| `psp-server` | Axum transport: SPA static serving, `GET /ws/{client_id}` WebSocket, `POST /api/convert/*`, Docker/native server management (`services/`), rfd file dialogs. Lib + bin. |
| `psp-desktop` | Tauri v2 shell (`tauri.conf.json`): spawns the embedded server on `127.0.0.1:5174`, bundles `ui_build` + `data` as resources. |
| `psp-web` | WASM cdylib wrapping `psp-app` for the browser webapp; built by wasm-pack into `ui/src/lib/wasm/psp`. |
| `ui/` | SvelteKit frontend (bun). See frontend section below. |
| `contract/fixtures/` | Golden WebSocket protocol fixtures replayed by `psp-server/tests/wire_contract.rs`. |
| `data/json/` | Game data (skills, items, breeding, map objects, `l10n/`). Manifest generated by `scripts/gen-json-manifest.mjs` before web/wasm builds. |
| `tests/fixtures/` | Reference save files for integration tests (`reference_saves/`, `saves/`, `world_option/`, `drg-save-test.sav`). |
| `scripts/` | Build orchestration (desktop/docker), version bump (`bump.ps1`), game-data generators, ooz WASM build. |

## Everyday commands

```bash
# Dev — preferred entry point (Linux/macOS; easyrun.ps1 on Windows)
./easyrun.sh --web        # Vite (5173) + psp-server (5174), tool-only SPA
./easyrun.sh --desktop    # Tauri window + embedded server
./easyrun.sh --webapp     # landing + tool, browser-only (VITE_TRANSPORT=worker)
./easyrun.sh --landing    # landing page only — no WASM, no server
./easyrun.sh --check      # preflight tool versions; --json for machine output
./easyrun.sh --serve      # Rust server alone

# Raw dev commands
cargo run -p psp-server -- --dev                    # --dev logs request timing
(cd psp-desktop && cargo tauri dev)                  # needs tauri-cli v2
(cd ui && bun run dev:web)                          # Vite + server via concurrently

# Rust checks — all required before commit
cargo fmt --all
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace                              # unit + integration + wire-contract
cargo test -p psp-server --test wire_contract -- --nocapture

# Frontend (from ui/, bun — not npm/yarn)
bun run check             # svelte-check
bun run lint              # prettier --check + eslint; `bun run format` to fix
bun run test:unit         # vitest (src/**/*.test.ts + scripts tests)
bun run test:integration  # playwright

# Builds
./scripts/build-desktop.sh        # or .ps1 — UI + cargo tauri build → dist/
(cd ui && bun run build:web)      # webapp bundle: wasm-pack + worker transport
(cd ui && bun run verify:build)   # sanity-check build output
docker compose up --build -d      # 3-stage Dockerfile (bun UI → cargo-chef → slim)
```

## The WebSocket message protocol

Single source of truth: `psp-app/src/messages.rs`. The
`define_message_types!` macro defines every message type; **the wire string is
the exact snake_case of the variant name** — renaming one requires an explicit
`#[serde(rename)]` plus the matching literal in the macro.

Adding or changing a message touches, in order:

1. `psp-app/src/messages.rs` — the variant.
2. A handler in `psp-app/src/handlers/*.rs` (domain-grouped: `pals.rs`,
   `players.rs`, `guilds.rs`, `ups.rs`, …), registered in the dispatcher.
   Server-management and native shell-open messages are the exception: they
   are routed to the transport crate via the trait in `dispatcher.rs` and
   implemented in `psp-server`.
3. The TypeScript mirror: `ui/src/lib/ws/types.ts` (`MessageType`) and a
   handler in `ui/src/lib/ws/handlers/` registered on the `MessageDispatcher`.
4. A fixture under `contract/fixtures/` if request/response behavior changed
   (see below).

Key runtime pieces in `psp-app`:

- `AppState` holds `Arc<dyn DbDriver>` (the persistence seam — every domain
  call runs SQL through it), a `FileDialogProvider` (rfd-backed in
  psp-server's desktop mode), and `SessionStore`.
- `SessionStore` keeps the last 8 parsed sessions keyed by id so a WebSocket
  reconnect (same `client_id`) reattaches without re-parsing the save.
- The dispatcher wraps handlers in `catch_unwind` — a panicking handler
  becomes an error response, not a dead connection.
- `progress_message` frames during long loads are part of the asserted
  protocol, not noise.

## Architecture rules (CI-enforced)

- **`psp-app` stays transport-free.** CI greps `cargo tree -p psp-app` and
  fails on `axum|rfd|opener|bollard|sysinfo|reqwest|tower-http|clap|sqlx`.
  Native/IO deps belong in `psp-server` or `psp-desktop` only. Same spirit:
  `psp-core` has no web deps; `psp-db` compiles with `--no-default-features`.
- **Core crates compile for `wasm32-unknown-unknown --no-default-features`**
  (`psp-core`, `psp-db`, `psp-app`); `psp-web` must build for wasm32. The
  `oodle` feature (C++ ooz codec) is default-on for native but OFF on wasm —
  browser Oodle decompression goes through the vendored WASM in `ui/vendor/ooz`
  and `ui/src/lib/worker/ooz.ts`.
- **The wire protocol is frozen unless changed deliberately.**
  `wire_contract.rs` replays committed fixtures and asserts exact response
  sequences. If a response legitimately changes, update that fixture — scoped
  to the intended change; an unexplained diff in an unrelated frame is a real
  bug. Irreducibly nondeterministic values are masked via `IGNORED_PATHS` /
  dedicated comparators, each with a justifying comment. The suite fails if
  the corpus is missing — it can never silently pass with zero coverage.
- **Schema changes** go through a new `psp-db/migrations/NNNN_*.sql` (sqlx
  migrate, embedded). The legacy `psp.db` importer (`import_legacy.rs`) runs
  once, guarded in the meta table.

## Frontend architecture (`ui/`)

- **SvelteKit with `adapter-static`** → outputs to `../ui_build`, consumed by
  both Tauri (`frontendDist`) and the Cloudflare deploy. Everything is
  prerendered (incl. localized paths); the `404.html` fallback pairs with
  wrangler's `not_found_handling: "404-page"` so unknown URLs return real 404s.
- **Path aliases** (svelte.config.js): `$components`, `$states`, `$ws`,
  `$types`, `$utils`, `$theme`, `$docs`, and `$i18n` (generated paraglide
  output — don't hand-edit `src/paraglide`).
- **State** is Svelte 5 runes in `.svelte.ts` stores: app/modal/theme state in
  `src/lib/states/`, domain data stores in `src/lib/data/*.svelte.ts`.
- **Components** are grouped by domain under `src/lib/components/` (pal,
  player, guilds, map, breeding, servers, tools, …) with shared primitives in
  `components/ui`.
- **i18n** is Paraglide/inlang: messages in `ui/messages`, URL strategy with
  cookie fallback (editor routes are deliberately unprefixed), routing config
  in `src/lib/i18n/routingConfig.js`. `bun run machine-translate` fills new
  keys.
- **Docs/wiki pages** use mdsvex (`.md`/`.svx` routes under `src/routes/docs`,
  wiki) with a shared TOC plugin (`remark-toc-headings.js`).
- **Webapp mode** (`VITE_TRANSPORT=worker`): `src/lib/worker/psp.worker.ts`
  runs the psp-web WASM off the main thread, handles sav↔gvas (zlib + Oodle),
  and persists via OPFS (`src/lib/fs/opfsBlobStore.ts`,
  `sessionPersistence.ts`) + sqlite-wasm (`worker/sqlite.ts`).

### Vite config gotchas (all deliberate — don't "fix" them)

- `strictPort: 5173`: Tauri's `devUrl` points here; drifting ports leave the
  desktop webview on a dead URL. `/api` proxies to the server on 5174.
- `optimizeDeps.exclude: ['@sqlite.org/sqlite-wasm']` — pre-bundling breaks
  its `locateFile` wasm lookup.
- **Icons are Iconify, not lucide-svelte.** Use `<Icon icon="tabler:device-floppy" />`
  from `ui/src/lib/components/ui/icons/Icon.svelte` (re-exported by the
  `$components/ui` barrel). Design language: **Tabler** primary, **Phosphor**
  (`ph:`) for gaps, `svg-spinners` for loading states, `line-md` for animated
  flourishes. Only used icons are bundled offline via
  `icons/subsets.generated.ts` — after adding/removing icons in source, run
  `node scripts/extract-icon-subsets.mjs` from `ui/` (a new icon renders blank
  in dev until you do). No icon data is fetched at runtime; desktop/webapp
  stay fully offline.
- `server.fs.allow` covers `ui/vendor` so the worker can load the vendored
  ooz wasm in dev.
- `ssr.noExternal` for `@skeletonlabs/*`, `@zag-js/*`, `maplibre-gl` — mixed
  zag versions resolve wrong when externalized.
- `VITE_HTTPS=1` (`dev:http2`) is opt-in: the cert is self-signed and the
  Tauri WebView2 won't load it.

## Build & release pipeline

- **CI** (`.github/workflows/ci.yml`, pushes/PRs): dependency guard + wasm32
  checks above, `cargo test --workspace`, then `bun run build` (desktop web
  build only).
- **Deploy-web** (`deploy-web.yml`): the **only** place `bun run build:web`
  runs — on release published (skips prereleases) or manual dispatch. Run it
  manually after any build-pipeline change; CI won't catch webapp breakage.
- **Desktop bundles** (Windows/Linux/macOS): `desktop-rust.yml` on release.
  Release also triggers `nexus-upload.yml` and `discord.yml`.
- Docker is self-build only; no prebuilt image is published. `PUBLIC_WS_URL`
  is a build arg baked into the SPA; the DB persists in the `./db` bind mount.
- `ui/.env` is written/restored by easyrun around dev runs (gitignored, with
  `.env.example` committed).

## Conventions & gotchas

- `uesave` is a **git dependency** (branch `pluggable-game-support`) pinned by
  `Cargo.lock`; update with `cargo update --package uesave`. For a local
  checkout, add a never-committed `[patch."https://github.com/oMaN-Rod/uesave-rs.git"]`
  section to root `Cargo.toml`.
- Version lives once in root `Cargo.toml` `[workspace.package]`; bump with
  `scripts/bump.ps1` — it feeds all crates, the Tauri bundle, and get_version.
- Container keys in saves are CityHash64 (`cityhasher` crate) — don't hand-roll
  hashing for them.
- Ports are load-bearing: Vite `5173` (strict), server `5174` (default +
  Docker EXPOSE + WS URL host).
- `psp-rs.db` at the repo root is a local dev database (gitignored, like all
  `*.db`); integration tests use `tests/fixtures/` and psp-core's
  `test-fixtures` feature (integration tests link the crate externally, so
  `cfg(test)` doesn't reach them).
- Formatting: Rust via `cargo fmt`; frontend via `ui/.prettierrc` (tabs,
  single quotes, no trailing commas, width 100, organize-imports + tailwind
  class sorting) — `bun run format` from `ui/`. Use `bun`; never npm/yarn.
- `sav → json → sav` round-trips only work within the same tooling
  generation; JSON exported by the retired Python tooling is rejected by
  `/api/convert/json-to-sav` by design.
